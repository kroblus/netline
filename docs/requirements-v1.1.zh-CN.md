# NETLINE — V1.1 追加需求：全局悬浮球与网速曲线图片分享

## 0. 任务说明与优先级

在现有 NETLINE Android 16 原生项目基础上，新增两个正式功能：

1. 全局悬浮球：在其他应用界面上方控制开始、停止网络流量记录。
2. 网速图表导出分享：将指定记录时间段的真实网络速度曲线、峰谷值和统计信息生成 PNG 图片，并分享给其他应用。

**这不是重新开发项目，而是一次增量功能扩展。**

保留之前确定的：

- Kotlin + Jetpack Compose
- Android 16，Target SDK 36
- TrafficStats 网速采样
- Room 历史存储
- Canvas 实时曲线
- Swiss International Typographic Style
- MVVM + Repository
- 最小权限和本地优先原则

原提示词中以下限制正式失效：

- 不实现悬浮窗
- 不声明悬浮窗权限

改为根据本次需求实现合规的全局悬浮球。

其他非目标限制继续有效。

请先检查已有代码、服务生命周期、数据库与 UI 实现，不要重复搭建已经存在的模块。

# 1. 全局悬浮球

## 1.1 核心目标

用户可以先打开 NETLINE，启用悬浮球，然后返回桌面或切换到其他应用。

悬浮球应在 Android 允许显示的普通应用窗口上方持续可见。

用户不需要重新打开 NETLINE 就可以：

- 点击悬浮球开始监控记录。
- 再次点击悬浮球停止记录。
- 拖动悬浮球改变位置。
- 通过悬浮球菜单打开 NETLINE 主界面。

停止记录不等于关闭悬浮球。

悬浮球必须能够处于待机状态，并可再次启动新的记录会话。

始终遵守 Android 16 对应用悬浮窗、后台服务与系统资源管理的限制，不得声称其能够覆盖所有系统界面或保证永久存活。

## 1.2 悬浮球外观

延续瑞士国际主义平面设计。

采用克制、高对比度、功能优先的设计。

悬浮球：

- 默认直径：56dp
- 最小触控区域：48dp
- 圆形
- 不使用玻璃拟态
- 不使用渐变
- 不使用复杂阴影
- 不使用闪烁动画
- 可选极轻微边框
- 视觉上应与主应用保持一致

状态 A — 待机：

- 深灰色 #242424
- 白色播放图标
- 无闪烁
- 内容描述：开始记录

状态 B — 记录中：

- 瑞士红 #E3342F
- 白色停止图标
- 内容描述：停止记录
- 可以显示非常小的静态记录状态点

状态 C — 操作处理中：

- 禁止重复操作
- 保留明确的状态反馈
- 不允许连续点击产生重复会话

只有在监控真正成功开始后，才能切换到记录中状态。

停止完成后恢复待机状态。

不允许仅仅因为按钮被点击就假装后台监控已经启动成功。

## 1.3 单击交互

定义明确状态机：

IDLE → STARTING → RECORDING → STOPPING → IDLE

单击行为：

如果 IDLE：

- 请求开始一个新的记录会话。
- 通过统一的 MonitorController 启动采样与持久化。
- 成功后更新悬浮球颜色。
- 失败时恢复待机状态并提供可理解的提示。

如果 RECORDING：

- 结束当前会话。
- 停止记录采样。
- 保存剩余数据。
- 更新悬浮球为待机样式。
- 悬浮球继续显示。

如果 STARTING 或 STOPPING：

- 忽略重复点击。
- 禁止创建额外会话。

必须防止：

- 双击产生两次开始动作。
- 一个点击被多层监听器重复消费。
- 服务和界面同时发起采样。
- 快速开始和停止造成数据损坏。

悬浮球、主界面和通知栏必须使用同一套真实监控状态。

## 1.4 拖动交互

实现拖动移动：

- 用户按住并移动悬浮球时进入拖动状态。
- 使用系统 touch slop 区分点击和拖动。
- 拖动过程中不触发开始或停止。
- 松开时允许吸附到最近的左侧或右侧屏幕边缘。
- 动画保持简短、自然。
- 保存悬浮球相对屏幕的最终位置。

位置存储使用 DataStore。

位置计算考虑：

- 状态栏
- 导航栏
- 手势导航区域
- Display Cutout
- 不同屏幕分辨率
- 设备旋转
- Android 16 的窗口 Insets

防止悬浮球移动到用户无法触碰的位置。

屏幕尺寸变化后应重新校正位置。

## 1.5 悬浮球功能菜单

当用户长按但没有明显拖动时，可以显示一个小型操作菜单。

菜单包含：

- OPEN NETLINE：打开主界面
- HIDE FLOATING BALL：隐藏悬浮球

菜单必须：

- 不影响当前记录会话。
- 不遮挡大面积应用内容。
- 点击菜单外部可关闭。
- 不产生意外的开始、停止操作。

长按与拖动的手势识别必须互斥。

隐藏悬浮球时，如果正在记录：

- 继续保持已经合法运行的记录会话。
- 允许通过通知栏或主界面停止记录。

如果没有运行中的记录会话：

- 释放不再需要的服务和视图资源。

## 1.6 悬浮球开启与关闭

在 NETLINE 设置中新增：

Floating Ball

开关：

ENABLE FLOATING BALL

启用后：

- 检查权限。
- 权限可用时创建悬浮球。
- 返回桌面后保持显示。
- 记录完成后保持显示。
- 持续显示直到用户主动关闭、撤销权限或系统限制导致不可用。

关闭后：

- 移除悬浮球。
- 清理 WindowManager View。
- 不影响已经开始的记录会话。
- 不留下悬浮窗资源泄漏。

悬浮球不是 App 安装后的默认强制行为。

第一次使用必须由用户明确启用。

不要默认在设备开机时自动开启悬浮球。

# 2. Android 16 悬浮窗权限与服务

## 2.1 悬浮窗权限

新增：

android.permission.SYSTEM_ALERT_WINDOW

使用：

Settings.canDrawOverlays(context)

检查权限。

使用：

Settings.ACTION_MANAGE_OVERLAY_PERMISSION

引导用户前往系统授权界面。

用户完成授权并返回后，重新检查权限。

不能直接假设权限已经成功授予。

权限被拒绝时：

- App 主界面继续正常工作。
- 常规开始、停止记录按钮继续可用。
- 提示悬浮球需要单独授权。
- 不强制要求用户授权才能使用网速监控核心功能。

如果运行过程中权限被撤销：

- 安全移除悬浮球。
- 避免 WindowManager 异常导致崩溃。
- 已运行的监控会话根据合法的服务生命周期继续或安全停止。
- 保留已采集的数据。

## 2.2 悬浮窗实现

使用：

WindowManager

WindowManager.LayoutParams.TYPE_APPLICATION_OVERLAY

要求：

- 只创建一个悬浮球实例。
- 使用适当的 NOT_FOCUSABLE 等窗口标志。
- 不默认获取输入焦点。
- 不干扰系统输入法。
- 不通过大面积透明窗口拦截其他应用的点击。
- WindowManager 窗口尺寸尽量与可交互内容匹配。
- 实现安全的 addView / updateViewLayout / removeView 生命周期管理。
- 处理重复添加和视图已经移除的情况。
- 不使用 AccessibilityService。
- 不使用隐藏 API。

可以通过原生 View 实现悬浮球，不强制在 WindowManager 上构建完整 ComposeView。

优先考虑兼容性、低内存占用和简单性。

## 2.3 后台运行架构

需要解决一个关键问题：

悬浮球在待机时仍然可能需要出现在其他应用上方，但此时不应该进行无意义的网速采样和历史数据写入。

将逻辑状态分离为：

- overlayEnabled
- overlayVisible
- recordingState
- activeSessionId

界面上的悬浮球状态必须来自权威状态源，而不是各组件内部独立维护的布尔变量。

允许设计独立的 OverlayController 或 OverlayHostService，但必须保证系统服务生命周期合法。

如果需要前台服务维持可见悬浮球：

- 先核对 Android 16 的官方服务规则。
- 说明所选前台服务类型的适用依据。
- 不能滥用 dataSync。
- specialUse 只能用于真实符合其定义的用途。
- 不得将持有悬浮窗权限当作所有后台启动限制的通用豁免。
- 对 Google Play 可能进行的前台服务用途审核进行说明。

特别检查：

Android 15 及更高版本中，依赖 SYSTEM_ALERT_WINDOW 例外从后台启动前台服务时，需要已经存在可见的应用悬浮窗，除非符合其他合法例外。

用户点击可见悬浮球启动记录时，检查实际服务启动路径是否符合要求。

如果某些设备或平台策略不能可靠支持长时间待机悬浮球：

- 不得使用循环重启或隐藏手段绕过。
- 必须清楚记录限制。
- 提供通过主界面重新启用的恢复方式。
- 不能伪造“永久在线”验收结果。

## 2.4 通知栏

悬浮球开启和记录中可以拥有不同通知状态。

记录中通知至少支持：

- 显示正在记录
- 打开 NETLINE
- 停止记录

如实际服务类型与系统通知要求适用，待机悬浮球阶段也应保持相应合规通知。

从通知栏停止记录和点击悬浮球停止记录必须得到完全相同的结果。

通知操作使用明确的 PendingIntent，并遵守 Android 16 的相关规则。

# 3. 网速图表导出分享

## 3.1 功能入口

主界面增加：

EXPORT CHART

历史会话详情也提供：

SHARE REPORT

点击后进入图片分享预览界面。

流程：

选择记录 → 选择时间范围 → 生成图片 → 预览 → 保存或分享

默认导出最近一次已经结束的监控会话。

若当前会话仍在记录中，可以导出截至当前时刻已经持久化并确认有效的数据，不暂停记录，也不强制结束当前会话。

## 3.2 时间范围

支持：

- Full Session：完整会话
- 60 Seconds
- 5 Minutes
- 15 Minutes
- 1 Hour
- Custom Range：自定义起止时间

历史列表中允许选择过去的任意监控会话。

选择时间范围时：

- 只包含实际采集到的数据。
- 不允许自动填充虚假数据。
- 不能把多个不连续会话假装成一个连续记录。
- 数据缺失必须保留。
- 没有有效数据时禁止导出，并显示原因。

如果范围跨多个会话，第一版优先提示用户选择单个会话，不必实现复杂会话拼接。

## 3.3 分享图片内容

图片应当是一张独立、完整、具有专业视觉设计的统计海报。

使用 Swiss International Typographic Style。

默认输出：

- PNG
- 1080 × 1920 像素
- 高分辨率
- 浅色背景
- 清晰字体
- 适合在微信、QQ 等聊天应用中查看

建议海报结构：

顶部：

NETLINE

NETWORK TRAFFIC REPORT

记录日期：

2026.10.16

监控时间段：

START / END

例如：

09:30:00 — 09:45:00

下一部分：

NETWORK SPEED OVER TIME

绘制真正的下载、上传双折线图。

下载：

深灰色 #202020

上传：

瑞士红 #E3342F

时间轴：

真实时间戳。

纵轴：

与数据一致的速度单位。

图表必须正确表示：

- 真实流量波动
- 峰值
- 谷值
- 网络空闲
- 数据缺失
- 突然升高的速度

重要：

不能为了图表看起来更好而修改数据。

不能通过过度平滑抹掉真实峰值。

不能把没有数据的区间补成零值。

图表降采样时优先保留局部最大值、最小值与时间顺序。

## 3.4 峰值与谷值标记

分别计算下载和上传速度：

- Peak Download
- Lowest Download
- Peak Upload
- Lowest Upload
- Average Download
- Average Upload

在图表上重点标记主要峰值和谷值位置。

标记应包含：

- 数据值
- 对应时间

对于最高和最低点：

- 从真实数据或保留精确极值的聚合数据中计算。
- 若多个点拥有相同极值，使用确定性的选择规则，例如最早时间。
- 有效的零速率可以作为谷值。
- 缺失采样不能作为谷值。

如果极值标记过于密集，应采用错位标注或引导线，保证可读性。

所有统计值与导出的数据范围保持严格一致。

## 3.5 底部统计面板

海报下方展示：

PEAK DOWN

LOWEST DOWN

AVG DOWN

PEAK UP

LOWEST UP

AVG UP

TOTAL RECEIVED

TOTAL SENT

DURATION

数据统计要求：

- 平均速度使用实际有效采样区间的字节数与时间计算。
- 总流量来自所选范围真实有效的字节增量。
- 缺失时间段不能计算成零流量。
- 如果覆盖率不足，应清楚标示实际有效采样时长。
- 不允许通过降采样后的图表点重新计算精确峰值。
- 不允许显示缺少依据的网络质量评分。

海报底部使用小号文字：

Generated by NETLINE

Traffic recorded on this device.

设备与网络统计可能存在系统计数器相关限制。

不需要上传任何数据到云端。

## 3.6 图片生成实现

新增独立的：

ChartExportRenderer

职责：

- 获取选定时间段的真实数据。
- 构建可复用的 ChartPlotData。
- 生成高分辨率位图。
- 绘制折线、坐标轴、标题、时间和统计数据。
- 输出 PNG。
- 返回成功或错误结果。

推荐使用 Android Canvas / Bitmap 创建独立的离屏渲染流程。

不要简单地截图整个 Dashboard 页面。

原因：

- 页面截图可能包含悬浮球。
- 页面截图不一定包含完整统计信息。
- 截图分辨率受设备影响。
- 页面可能存在可滚动区域。
- 图片导出需要可控的固定排版。

屏幕图表和导出图表应复用相同的数据处理、时间映射、峰谷计算逻辑，避免同一时间段出现不同统计结果。

Bitmap 编码放在后台线程。

控制内存分配，导出后及时释放不再使用的位图对象。

## 3.7 图片预览

新增 ExportPreviewScreen。

预览页面必须包含：

- 生成的图片
- 保存图片按钮
- 分享图片按钮
- 返回按钮

图片可在页面内缩放查看，但不需要开发复杂图片编辑器。

保存按钮：

SAVE IMAGE

分享按钮：

SHARE IMAGE

保存与分享是两个独立操作。

# 4. 保存与系统分享

## 4.1 保存到相册

使用 Android MediaStore。

将 PNG 保存到：

Pictures/NETLINE/

文件名示例：

NETLINE_20261016_093000_094500.png

使用：

MediaStore.Images.Media

RELATIVE_PATH

IS_PENDING（在适用系统版本上）

要求：

- 防止出现未写完的损坏文件。
- 文件写入完成后再显示成功。
- 保存失败给出明确提示。
- 不覆盖已有文件。
- 避免同名文件冲突。
- 用户可以在系统相册中看到图片。

在 Android 10 及更高版本，对应用自己创建的图片通常不需要申请通用存储访问权限。

本项目最低版本为 Android 10，因此不要因为保存图片而增加不必要的 READ_MEDIA_IMAGES、READ_EXTERNAL_STORAGE 或 WRITE_EXTERNAL_STORAGE 权限。

## 4.2 分享到其他应用

使用：

Intent.ACTION_SEND

MIME：

image/png

使用：

Intent.EXTRA_STREAM

通过：

FileProvider

提供安全的 content:// URI。

需要：

- FLAG_GRANT_READ_URI_PERMISSION
- 正确配置 FileProvider
- 使用系统 Sharesheet
- 不暴露 file:// 路径
- 不使用公开可访问的临时文件路径
- 不要求用户先手动保存到相册

点击 SHARE IMAGE 时：

直接打开系统分享界面。

用户可以选择已安装且支持图片接收的应用。

例如：

- 微信
- QQ
- 邮件
- 蓝牙
- 其他聊天软件

不能假设这些应用一定已经安装。

若没有合适的目标应用，显示可理解的提示。

分享完成后，不自动删除用户已经保存到相册的正式图片。

临时导出文件按合理策略清理，避免缓存无限增长。

# 5. 数据模型补充

原有 Room 历史数据模型需要扩展。

特别是 MinuteAggregate：

除了原有的总收发字节、有效采样时长、平均速度和峰值速度，还需能够保留：

- 最低有效下载速度
- 最低有效上传速度
- 峰值对应的时间
- 谷值对应的时间
- 有效样本数量
- 缺失数据或采样覆盖信息

这用于在早期秒级数据已被清理后，仍然生成可信的较长时间范围报告。

要求：

- 使用 Room Migration 迁移数据库。
- 不得为了添加字段直接删除用户已经保存的历史记录。
- 数据结构必须与实际统计精度一致。
- 不能凭空恢复旧聚合记录中未存储的峰谷时间。
- 如旧数据精度不足，明确标示对应统计信息不可用。
- 允许基于当前数据保留策略给出导出范围和精度说明。

# 9. 最终验收标准

## Floating Ball

PASS 条件：

- Android 16 真机授权成功。
- 能在桌面和其他普通应用上方显示。
- 单击可以真正开始记录。
- 再次单击可以真正停止记录。
- 记录状态与实际服务和数据库保持一致。
- 拖动和点击不冲突。
- 停止记录后悬浮球保持可用。
- 不会生成重复采样器或重复会话。
- 没有明显服务生命周期异常。

如果没有真机验证，标记 PASS WITH RISKS 或未验证，不得假装所有设备均已通过。

## Chart Export

PASS 条件：

- 图片来自真实历史数据。
- 峰值、谷值、平均值可验证。
- 时间范围准确。
- 图片清晰完整。
- PNG 文件能够正常打开。
- 能够保存到相册。
- 能够通过系统分享界面发送给其他应用。
- 数据间断不会被伪造成连续曲线。
- 图片风格与 NETLINE 主界面保持一致。

## 技术质量

必须保持：

- 可编译
- 低额外功耗
- 没有不必要的互联网权限
- 没有文件系统过度授权
- 正确的 Android 16 服务权限
- 没有前台 UI 与后台服务重复采样
- 无不必要的主线程数据库或图片编码操作
